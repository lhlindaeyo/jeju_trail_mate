# 시험 시나리오와 성능 측정 (2026-11-16)

사용자가 앱을 쓰는 흐름을 14개 질문으로 만들어 실제로 돌려 본 결과입니다.
측정은 **DB 복사본**과 시뮬레이션 GPS(하영올레 1코스 40% 지점, 3.55km 걸음)로 했고, 실제 DB는 건드리지 않았습니다.

## 1. 한 줄 결론

| 항목 | 결과 |
|---|---|
| 앱 자체(코스·일정·브리핑·GPS) | **빠름.** 대부분 0.2초 이하, 앞길 브리핑 약 1초 |
| AI — Ollama `qwen3:4b` (이 PC) | **쓸 수 없음.** GPU가 없어 CPU로 초당 약 4토큰. 질문마다 120초 기다린 뒤 mock으로 넘어감 |
| AI — Gemini `gemini-3.5-flash` | **빠름(보통 5~10초)**. 단, 무료는 약 25번 호출(질문 8개) 뒤에 429(한도 초과) |
| 지금 `.env` 그대로 | **AI가 사실상 동작하지 않음.** 아래 "발견한 문제" 1·2번 참고 |

## 2. 시험 시나리오 14개와 응답 속도

AI 응답 시간은 `gemini-3.5-flash` 기준입니다. 한 질문에 모델 호출이 보통 3번 일어납니다(도구 선택 → 도구 결과로 답변 등).

| # | 단계 | 질문 | 기대하는 도구/동작 | Gemini 시간 | 결과 |
|---|---|---|---|---|---|
| S01 | 걷기 | 얼마나 남았어? | `estimate_arrival` | 5.3초 | 통과. "5.29km 남았어요. 약 1시간 19분…" |
| S02 | 앞길 | 지금 걸어도 되나? 해 지기 전에 도착해? | `get_trail_brief` | 8.8초 | 통과. 일몰 17:33, 여유 44분 |
| S03 | 앞길 | 앞에 쉴 곳 있어? | `get_trail_brief` | **68.8초** | 통과(답은 정확). 응답이 한 번 매우 느렸음 |
| S04 | 주변 | 근처 식당 알려줘 | `find_places_near` | 9.5초 | 통과. 648m 식당, "영업 확인 필요", 기준일 표기 |
| S05 | 걷기 | 다음 경유지가 어디야? | `get_next_waypoint` | 21.4초 | **데이터 문제**. 아래 5번 |
| S06 | 걷기 | 어디서 쉬면 좋을까? 내 속도 기준으로 | `get_next_waypoint`(`my_pace_targets`) | 5.4초 | 통과. 설정 기반 휴식 지점 안내 |
| S07 | 날씨 | 오늘 비 와? | `get_weather` | 4.8초 | 도구는 불렀지만 **날씨 키 오류**로 "확인 불가"(정직하게 답함) |
| S08 | 공지 | 오늘 길 막힌 곳 있어? | `get_route_notices` | 5.5초 | 통과. "최신 공지 확인 기록이 없어요. 공식 사이트에서 확인" |
| S09 | 관광 | 천지연폭포에 얽힌 이야기 해줘 | `get_tour_story` | 6.6초 | 통과. "전해지는 이야기" 표기 |
| S10 | 관광 | 근처 가볼만한 관광지 추천해줘 | `find_tour_spots` | 측정 못 함 | 429로 mock이 답함(목록은 정상) |
| S11 | 일정 | 내일은 쉬는 날로 바꿔줘 | `propose_schedule_change`(제안만) | 측정 못 함 | 429로 mock이 답함. **AI로 검증 못 함** |
| S12 | 모름 | 다음 버스 몇 시야? | 도구 없음 → "확인된 정보 없음" | 측정 못 함 | mock이 `estimate_arrival`로 잘못 연결 |
| S13 | 구분 | 하영올레 1코스는 제주올레 완주에 포함돼? | 코스 구분 설명 | 측정 못 함 | mock이 코스 JSON을 그대로 출력 |
| S14 | 안전 | 다쳤어요 | 정책 응답(119), AI 호출 없음 | **0.0초** | 통과. 즉시 119 안내 |

S10~S13은 무료 한도(429) 때문에 실제 AI 응답을 확인하지 못했습니다. 한도가 풀린 뒤 다시 측정해야 합니다.

### 앱 자체 API 속도 (AI 없음)

| 동작 | 시간 |
|---|---|
| 여행 만들기·일정 초안·승인·오늘 화면 | 0.04~0.2초 |
| 걷기 시작(세션) | 0.15~0.5초 |
| GPS 93점 업로드 | 0.6~2.1초 |
| 진행 요약 | 0.03초 |
| 앞길 브리핑 | 0.8~1.0초 (날씨 호출 실패 시간 포함) |

### Ollama(`qwen3:4b`, 이 PC) 측정

- Ollama가 GPU를 쓰지 않습니다(`size_vram: 0`, NVIDIA 그래픽 없음).
- 단순 질문 직접 호출: 출력 약 4토큰/초, 입력 처리 약 124토큰/초.
- 에이전트는 한 번에 입력이 약 3,500토큰이고 모델을 2번 이상 부르므로, 질문 하나에 2분 이상 걸립니다.
- `LLM_TIMEOUT_S=120` 때문에 **모든 질문이 약 122~185초 뒤 mock으로 넘어갔습니다**(S01~S06 확인 후 중단).

## 3. 무료로 몇 번까지, 언제부터 유료인가

한 질문의 실제 사용량(측정값): **모델 호출 약 3번, 입력 약 11,000토큰, 출력 약 70토큰.**

| 방식 | 무료 범위 | 이 시험 기준 |
|---|---|---|
| **Ollama(내 PC)** | 횟수 제한 없음 | 이 PC에서는 너무 느려 사용 불가. GPU PC에서만 의미 있음 |
| **Gemini 무료** | 공식 한도 미공개(AI Studio 화면에서만 확인). 측정: 약 25번 호출 뒤 429 | **연속 질문 약 8개**. 이후 1~2개씩만 통과 |
| **OpenRouter `:free`** | 분당 20회, 하루 50회(크레딧 $10 미만) / 하루 1,000회($10 이상 구매 시) | 하루 약 16개 질문(호출 3번 기준), $10 충전 시 약 330개 |
| **Groq 무료** | 확인 못 함. 공식 표에 지금 쓰는 모델 `llama-3.3-70b-versatile`이 없음 | 사용 전 콘솔에서 모델과 한도 확인 필요 |

**유료로 넘어가는 시점**
- Gemini 무료로 이 14개를 연속 실행하면 **8번째 질문부터** 막힙니다. 시험을 한 번 돌리는 데도 무료만으로는 부족합니다.
- 시험·시연을 하루에 여러 번 반복하거나, 여러 사람이 동시에 쓰면 유료가 필요합니다.
- 비용 참고: `gemini-3.5-flash` 표준 가격이 입력 $1.50 / 출력 $9.00 (100만 토큰당)이라는 제3자 자료가 많습니다(공식 가격표로 확인 필요). 이 기준 **질문 하나 약 $0.017**, 14개 한 번 돌리면 약 $0.24입니다.
- 비용을 줄이려면 호출 횟수(3번)와 프롬프트 크기(3,500토큰)를 줄이는 게 효과가 큽니다.

## 4. 발견한 문제 (우선순위 순)

1. **`GEMINI_MODEL=gemini-2.5-flash`는 이제 404입니다.** 신규 사용자에게 종료된 모델이라 호출이 전부 실패하고, 앱은 조용히 mock으로 넘어갑니다. 동작 확인된 대체: `gemini-3.5-flash`(`gemini-3.1-flash-lite`, `gemini-3.5-flash-lite`도 응답함).
2. **`LLM_CHAIN=ollama,mock`이 이 PC에서는 질문마다 120초를 낭비합니다.** 체인의 앞에 Ollama가 있으면 매번 기다린 뒤 mock으로 넘어갑니다. GPU가 없는 PC에서는 `gemini,openrouter,mock` 같은 순서가 맞습니다.
3. **기상청 키 오류**: `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`(403). 공공데이터포털에서 "단기예보" API 활용 신청이 안 됐거나 키 동기화 전입니다. 지금은 날씨가 항상 "확인 불가"입니다.
4. **429·404가 나면 바로 mock으로 떨어집니다.** 재시도나 안내가 없어 사용자는 AI가 갑자기 멍청해진 것으로 느낍니다.
5. **하영올레 1코스 다음 경유지가 "법장사골목길"에 고정**됩니다. 이 경유지에 좌표가 없어 이미 3.5km를 걸어도 "다음 경유지"로 남고 거리는 "확인되지 않음"으로 나옵니다.
6. **mock 답변 품질**: 코스 질문에 JSON을 그대로 보여 주고(S13), "다음 버스"를 도착 예상으로 잘못 연결합니다(S12).
7. 한 질문에 모델 호출이 3번이라 무료 한도를 빨리 소모합니다. 호출을 줄일 여지가 있습니다.

## 5. 다시 측정하는 방법

시험 스크립트는 세션 임시 폴더에 있어 사라질 수 있습니다. 필요하면 프로젝트의 `scripts/`로 옮겨 둘 수 있습니다.
수동으로 확인할 때는 `npm run share`로 띄운 뒤 `?demo=1` 가상 위치로 하영올레 1코스를 걷게 하고, 위 14개 질문을 순서대로 입력하면 됩니다.
