01. 제품 개요

JEJU TRAIL MATE는 제주올레길을 걷는 개별 여행자를 위해 계획·이동·현장 대응·기록·완주 기념책 제작을 하나로 연결하는 개인화 AI 트레킹 에이전트다.

PLAN

여행 전

여행 기간, 체력, 선호도, 귀환 시각을 반영해 여러 코스의 일정을 계획한다.

WALK

여행 중

위치·진행률·날씨·일정을 결합해 유용한 순간에 먼저 안내한다.

REMEMBER

여행 후

사진·음성·텍스트 기록을 정리해 하루 일기와 완주 디지털 책을 만든다.

제품 원칙

  • 사용자 주도권: AI는 추천·초안을 제안하고, 일정 변경·공유·삭제는 사용자가 승인한다.
  • 검증된 정보: 코스·우회·운영 정보는 출처와 갱신 시각을 함께 표시한다.
  • 걷기에 방해되지 않기: 알림은 최소화하고 음성 입력과 한 손 조작을 지원한다.
  • 기록의 진정성: AI는 사용자가 말하지 않은 사건·감정을 지어내지 않는다.
  • 오프라인 대비: 네트워크가 끊겨도 저장된 일정·기록·기본 코스 정보에 접근할 수 있게 한다.
제품 포지셔닝: 단순 지도 앱이나 관광 챗봇이 아니라, 개인의 여행을 관리하고 그 경험을 기억 가능한 결과물로 완성하는 AI 동행자.

02. 공식 제주올레 사이트 기반 설계

기준 사이트: 제주올레 트레일 공식 페이지

437km
공식 사이트가 안내하는 전체 길이
27개
공식 사이트가 안내하는 코스 수

공식 페이지는 코스별 이름, 난이도, 거리, 예상 소요 시간과 함께 긴급 알림 및 코스 변경·우회 공지를 제공한다. 이러한 정보는 코스 탐색과 안전 안내의 출발점으로 삼는다.

공식 사이트와의 연동 원칙

데이터제품 활용구현 원칙
코스 이름·번호코스 검색, 일정 구성공식 제공 자료 또는 사용 허가를 받은 데이터로 관리
거리·난이도·예상 시간개인화 추천 및 일정 추정수집 날짜와 원본 출처를 저장하고 변경을 감지
코스 GPX·경로 좌표지도 표시, 진행률 계산공식 다운로드/API 제공 여부와 라이선스를 먼저 확인
긴급 알림·우회 공지트레킹 중 안전 알림공식 공지의 최신성을 확인하고, 확인 불가 시 최신 정보로 단정하지 않음
스탬프·완주 정보완주 기록 및 기념책공식 인증과 앱 자체 기록을 명확히 구분
중요한 데이터·권리 확인: 웹페이지에 보이는 정보라고 해서 자동 수집·재배포·상업적 이용이 허용되는 것은 아니다. 공식 기관에 데이터/API·지도·GPX·상표·사진 사용 조건을 확인한다. 웹 스크래핑을 기본 전제로 삼지 말고, 허가된 데이터 제공 방식 또는 수동 관리가 가능한 초기 데이터셋으로 시작한다.

데이터 갱신 전략

  1. 코스 메타데이터는 관리자 검토 후 버전 관리한다.
  2. 우회·통제 공지는 가능하면 공식 피드/API를 이용한다. 제공되지 않으면 관리자 확인·수동 등록 절차를 둔다.
  3. 각 데이터 항목에 source_url, checked_at, valid_from, valid_until을 기록한다.
  4. 오래되었거나 확인되지 않은 정보에는 “최신 확인 필요” 배지를 표시한다.

03. 타깃 고객과 문제 정의

Primary

여러 코스를 걷는 개별 여행자

일정을 직접 짜야 하고, 걷는 중 교통·식사·휴식·귀환까지 판단해야 한다.

Secondary

혼자 걷는 여행자

안전과 귀환 계획이 중요하며, 경험과 감정을 기록으로 남기고 싶어 한다.

Secondary

감성·사진 중심 여행자

사진은 많이 찍지만 일기를 미루기 쉽고, 여행 후 기록을 정리하기 어렵다.

Future

외국인 올레길 여행자

다국어 안내, 교통 정보, 쉬운 코스 설명이 필요하다.

핵심 사용자 문제

문제제품의 해결측정할 지표
여러 사이트를 오가며 일정 조사코스·시간·선호도를 통합한 일정 초안계획 완성 시간, 추천 채택률
날씨나 속도 변화에 대응하기 어려움상황 감지 후 대안 제안알림 유용성, 일정 조정 성공률
걷는 중 휴대폰 조작 부담음성 입력, 요약형 알림, 큰 버튼기록 작성 시간, 알림 무시율
여행 감정과 순간을 잊어버림음성·사진으로 즉시 메모일기 기록 일수, 저장률
완주 후 기록을 정리하지 못함AI 편집 가능한 디지털 여행책책 생성률, 만족도, 공유·다운로드

04. 핵심 사용자 여정

1. 여행 시작 전 — 여행 프로필과 일정

사용자는 날짜, 숙박 위치, 하루 최대 거리, 걷기 종료 시각, 풍경·카페·문화 선호, 이동 수단을 입력한다. AI는 코스 조합과 이동 일정을 제안하며, 사용자가 승인한 일정만 확정한다.

완료 기준: 일정에 날짜별 코스, 예상 시간, 시작·종료 지점, 이동·숙박 확인 필요 항목이 들어간다.

2. 출발 전 — 오늘의 브리핑

오늘의 코스, 예상 거리와 시간, 날씨 출처·갱신 시각, 준비물, 공식 우회 공지 확인 여부를 보여준다. 정보가 불확실하면 명확히 표시한다.

3. 걷는 중 — 실시간 상황 지원

사용자가 트레킹 세션을 시작하면 GPS를 기록한다. 계획보다 늦어짐, 장시간 이동, 공식 우회 공지, 일몰 임박 등 유용한 조건에서만 알림을 생성한다.

4. 순간 기록 — 음성·사진·텍스트

사용자는 “오늘 바다가 정말 예뻤어”라고 말하거나 사진을 저장한다. 앱은 시간·위치와 연결하고 AI 일기 초안을 만든다. 사용자가 수정·저장한다.

5. 하루 종료 — 일기 확인

하루 이동 요약, 사진, 음성 메모, 방문 장소를 모아 일기 초안을 생성한다. AI가 추측한 내용은 추가하지 않고, 위치 기록 누락은 추정 사실처럼 쓰지 않는다.

6. 여행 완료 — 디지털 일기책

사용자는 표지 제목, 대표 사진, 책 스타일을 선택한다. AI는 프롤로그·날짜별 기록·여정 지도·통계·에필로그를 구성하고 PDF를 생성한다. 사용자가 미리 보고 최종 승인한다.

모바일 UX 규칙

  • 걷는 중 핵심 버튼은 크고 간결하게 배치하며, 긴 텍스트 입력을 요구하지 않는다.
  • 알림 문구는 짧게 쓰고, “지도 보기”, “일정 다시 계산”, “나중에”처럼 선택지를 명확히 제공한다.
  • 이동 중 화면을 오래 보게 만드는 UI를 피하고, 음성 기능은 사용자가 직접 시작한다.
  • 색상만으로 상태를 전달하지 않고 텍스트·아이콘을 함께 쓴다.
  • 네트워크 오류, 위치 권한 거부, GPS 정확도 낮음 상태를 명확하게 안내한다.

07. AI Agent 설계

초기 버전은 여러 LLM 에이전트가 서로 대화하는 구조보다, 하나의 오케스트레이터가 도구를 선택하는 구조로 만든다. 시간·거리·경로 계산은 코드로 처리하고 LLM은 의도 파악, 설명, 초안 생성에 집중한다.

1. Input
사용자 메시지, 현재 일정, 세션 상태, 사용자가 허용한 위치·날씨 정보
↓
2. Context Builder
필요한 최소 데이터만 조회: 선호, 오늘 일정, 최근 이동 요약, 관련 공지
↓
3. Intent & Policy
일정 질문 / 장소 검색 / 안전 관련 질문 / 일기 / 완주 책 / 일반 대화 분류
↓
4. Tool Router
RouteService · WeatherService · POIService · ScheduleService · JournalService · BookService
↓
5. Verified Result
외부 데이터 출처·시간·신뢰 상태 확인, 필요 시 결과 부족을 명시
↓
6. Response / Approval
짧은 답변과 선택지를 제공. 일정 변경·공유·삭제 등은 사용자 확인 후 실행

도구 인터페이스(예시)

get_route(route_id)
get_route_notices(route_id, checked_after)
get_weather(lat, lon, time_range)
get_nearby_places(lat, lon, category, open_status)
estimate_arrival(route_progress, walking_pace, break_plan)
propose_schedule_change(trip_id, constraints)
create_journal_draft(entry_ids, user_style)
generate_journey_book(trip_id, selected_entries, theme)

LLM이 하면 안 되는 일

  • 존재 여부를 확인하지 않은 식당·쉼터·버스 시간을 만들어내기
  • 공식 코스 통제 상태를 실시간 확인 없이 단정하기
  • 사용자 동의 없이 일정·예약·공유 설정을 변경하기
  • 일기에서 사용자가 말하지 않은 감정·사건·대화를 사실처럼 쓰기
  • 위치·활동 데이터만으로 의료적 진단이나 안전 보장을 하기

개인화 메모리

사용자가 저장에 동의한 선호(선호 거리, 풍경, 휴식 빈도, 문체 등)만 장기 프로필에 저장한다. 임시 GPS는 필요한 기간만 보유하고, 원시 위치 기록을 LLM에 매번 통째로 보내지 않는다. 개인화 기억을 열람·수정·삭제할 수 있는 설정을 제공한다.

11. 능동 알림 엔진

모든 위치 업데이트마다 LLM을 호출하지 않는다. 저비용 규칙 엔진이 이벤트를 감지하고, 사용자 의사결정에 도움이 될 때만 AI가 맥락에 맞는 문구와 대안을 만든다.

이벤트판단 로직 초안사용자 경험가드레일
일정 지연예상 진행률과 실제 진행률의 차이가 설정 기준을 초과도착 시간 재계산, 휴식/종료 지점 선택GPS 정확도가 낮으면 지연을 단정하지 않음
휴식 제안사용자 설정 시간 이상 이동했고 알림 허용 상태가까운 휴식 장소 또는 쉬기 제안의학적 피로 진단 금지, 빈도 제한
날씨 변화공식 데이터의 조건/특보 변화최신 예보 출처와 확인 시각 표시실시간 데이터가 없으면 “예보 확인 필요”
우회·통제 공지관련 코스의 유효한 공식 공지공지 요약, 원문 열기, 일정 재검토공지 확인 실패 시 안전한 최신 정보로 단정 금지
일몰/종료 시각 임박예상 남은 시간과 사용자 종료 목표 비교안전한 종료 지점/귀환 수단 확인 제안경로·교통 정보가 검증되지 않으면 대안 확정 금지
기록 제안사용자 설정에 따라 세션 종료 후 또는 장소 저장 후“오늘 기억하고 싶은 순간이 있나요?”사용자가 끌 수 있으며 안전 알림과 분리

알림 중복 방지

  • event_key + session_id + time_window 기준으로 중복 이벤트를 억제한다.
  • 사용자가 닫거나 “오늘은 그만”을 선택하면 동일 유형 알림을 일정 시간 억제한다.
  • 중요한 안전 공지와 일반적인 기록 제안을 별도 우선순위로 관리한다.
  • 알림을 보냈는지뿐 아니라 확인/무시/행동 선택을 기록하되, 과도한 추적은 피한다.

실행 의사코드

on_location_batch(session, points):
  if not session.user_enabled_tracking:
      return

  summary = update_route_progress(points)
  events = rules_engine.evaluate(
      summary,
      session.approved_schedule,
      latest_verified_notices,
      user.notification_preferences
  )

  for event in deduplicate(events):
      if event.is_safety_related:
          message = build_verified_safety_message(event)
      else:
          context = load_minimal_context(event, session.user_id)
          message = ai.generate_suggestion(context, event)

      send_notification_if_allowed(message)
      log_delivery_status(event)

규칙:
- 제공되지 않은 사건, 대화, 감정, 장소를 만들어내지 않는다.

- 기록이 부족하면 짧게 쓰거나 사용자에게 추가 질문한다.
- 초안임을 표시하고 사용자가 수정하기 전에는 최종 기록으로 간주하지 않는다.

13. 보안·개인정보·안전

권한과 동의

  • 위치 권한은 기능 사용 직전에 목적을 설명하고 요청한다. 항상 위치 권한을 기본으로 요구하지 않는다.
  • 마이크·사진·AI 처리 동의는 각각 구분하고, 철회 방법을 제공한다.
  • 위치 추적은 사용자가 트레킹 세션을 시작한 경우에만 수행하며, 일시정지/종료가 명확해야 한다.
  • 사용자가 선택하지 않은 위치·음성 데이터는 개인화 학습이나 다른 목적으로 재사용하지 않는다.

보안 기본 요구사항

  • 전송 중 HTTPS, 저장 시 서비스가 지원하는 암호화, 비밀키의 서버 보관
  • DB row-level security 또는 서버의 소유권 검사로 사용자 간 데이터 격리
  • 미디어 파일은 비공개 저장, 짧은 만료의 서명 URL 사용
  • LLM 프롬프트와 로그에 원시 GPS·음성 전체를 불필요하게 남기지 않음
  • 계정 삭제 시 원본 파일, 파생 PDF, 캐시와 백업의 삭제/만료 정책 적용
  • API rate limit, 입력 검증, 업로드 용량·파일 형식 제한, 관리자 권한 분리

안전 설계

이 앱은 구조·구급 서비스가 아니며, GPS나 예보만으로 안전을 보장하지 않는다. 위급한 경우 현지 공식 긴급 연락 및 구조 안내를 우선하도록 명확히 안내한다.
  • 공식 통제·우회 공지의 최신 여부와 확인 시각을 표시한다.
  • 위치가 부정확하거나 데이터가 오래되면 경로 안내 신뢰도를 낮춰 표시한다.
  • 위험 상황에서 AI가 임의의 지름길을 제안하지 않도록 한다.
  • 실시간 교통·영업 상태가 연결되지 않았다면 “확인된 정보”라고 표시하지 않는다.
  • 사용자가 선택한 신뢰 연락처 공유 기능은 별도 동의·테스트가 완료된 후 추가한다.

초기 데이터 범위

  1. 공식 출처 및 사용 조건을 확인한 코스 메타데이터를 우선 등록한다.
  2. 경로 좌표/GPX 사용 권한을 확보하기 전에는 공식 홈페이지로 연결하거나 지도에서 이용자가 선택한 지점을 안내하는 방식으로 제한한다.
  3. 주변 장소는 검증된 POI 제공자 한 곳으로 시작하고, 정보가 부족한 경우를 UI에서 명확히 표시한다.
  4. 첫 현장 테스트는 1~2개 코스로 한정해 GPS·일기·책 생성 품질을 확인한다.

15. 개발 로드맵

가정: 소규모 개발팀 1~2명, 주 5일 기준. 외부 데이터 사용 승인과 앱 심사 기간은 별도이며, 실제 일정은 기술 검증 후 조정한다.

1주 차 — 요구사항·데이터 검증

공식 코스 데이터 사용 가능성 확인, 사용자 인터뷰, 핵심 플로우, 디자인 시스템, 개인정보 흐름 설계.

산출물: PRD · 화면 흐름 · 데이터 출처표

2주 차 — 프로젝트 기반

모바일 앱/웹 셋업, 인증, DB, 스토리지, 프로필·여행 CRUD.

산출물: 로그인 가능한 앱

3주 차 — 코스와 일정

코스 검색·상세, 일정 생성·수정, 승인 버전, 지도 표시.

산출물: 계획 수립 플로우

4주 차 — 트레킹 세션

GPS 권한, 시작/일시정지/종료, 거리·시간 계산, 위치 오류 처리.

산출물: 현장 기록 가능한 빌드

5주 차 — AI Agent와 알림

도구 호출, 검증된 데이터 조회, 일정 지연·공지 알림, 중복 억제.

산출물: 맥락 기반 동행자

6주 차 — 저널

음성 전사, 사진 첨부, 위치/시간 연결, AI 초안 편집·저장.

산출물: 하루 일기 완성

7주 차 — 디지털 책

템플릿, 페이지 나눔, 지도·통계, PDF 미리보기와 다운로드.

산출물: 완주 책 생성

8주 차 — 현장 테스트와 개선

실제 트레킹 테스트, 배터리·오프라인·권한·접근성·일기 품질 검증.

산출물: MVP 후보 버전
백그라운드 GPS, 오프라인 지도, 안정적인 푸시 동작은 모바일 OS 정책과 지도 SDK 제약에 영향을 받으므로 3~4주 차부터 실제 기기에서 검증한다.

16. 테스트 계획과 성공 지표

핵심 테스트 케이스

영역테스트기대 결과
계획사용자가 하루 거리·종료 시각을 변경영향받는 일정 재계산, 승인 전 확정 변경 없음

알림동일 이벤트 반복 발생중복 알림 억제 및 설정 반영
공지공식 공지 데이터가 오래되거나 조회 실패최신 정보로 단정하지 않고 확인 필요 표시
AI존재하지 않는 장소를 질문확인 불가를 설명하고 검증된 검색만 제안
일기음성 기록에 장소·감정이 불명확추측하지 않고 중립적 초안 또는 추가 질문

19. 출처와 가정

공식 및 참고 링크

  1. 제주올레 트레일 공식 코스 안내 — 코스 목록, 거리·난이도·예상 시간, 공지 확인의 기준 출처.
  2. 사단법인 제주올레 소개 — 제주올레의 목적 및 공식 단체 정보.

문서 해석 시 주의

  • 이 문서는 개발 착수를 위한 제품 요구사항 및 기술 설계 초안이다. 실제 API 제공 여부, 가격, 이용약관, 앱 심사 조건은 구현 전에 각 공급자의 최신 문서로 검증해야 한다.
  • 공식 홈페이지에서 확인한 코스 수·총길이·코스 속성은 변경될 수 있으므로 데이터베이스에 고정 상수로만 넣지 말고 출처·확인 시각·버전을 관리한다.
  • 화면, API 경로, 데이터베이스 스키마는 제안안이며 실제 개발 중 기술 검증과 사용자 조사 결과에 따라 수정한다.
  • 이 제품은 공식 제주올레가 운영·보증하는 서비스가 아니다. 제휴나 공식 승인을 받기 전에는 공식 서비스로 오인될 표현·브랜딩을 피한다.
